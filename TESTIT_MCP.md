# Подключение Test IT MCP к Codex

Настройка подготовлена по [документации Test IT](https://docs.testit.software/user-guide/mcp/mcp-setup.html)
и [документации Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

## Настройка

В корневом `.env` используются `URL_TESTIT_ADDRESS` и `TOKEN_TEST_ID`.
Локальный STDIO-адаптер `scripts/testit_mcp_adapter.py` подключается к серверу
по адресу URL с постфиксом `/mcp`. Заголовки `X-baseurl` и `X-token`
формирует `scripts/testit_mcp_headers.py`, читая `.env` при подключении.
Токен не копируется в TOML и не передаётся в аргументах командной строки.
Не запускайте скрипт заголовков вручную: его stdout предназначен только для MCP-клиента.

Готовая конфигурация без токена сохранена в `testit_mcp.config.toml`, но этот файл
сам по себе не подключает MCP. Установить адаптер можно из корня проекта:

```bash
python3 scripts/install_testit_mcp.py --adapter --replace-testit
```

Установщик добавляет сервер `testit` в проектный `.codex/config.toml`, сохраняет
существующие настройки. С `--replace-testit` он сохраняет резервную копию всего файла
и заменяет только таблицу `testit`; без флага отличающаяся запись не перезаписывается.
Чтение `.env` не требует `python-dotenv`: поддерживаются значения в одной строке,
одинарные и двойные кавычки, `export` и комментарии. Подстановка переменных не выполняется.
Для установщика на Python 3.10 нужен `tomli`; на Python 3.11 и новее используется
встроенный `tomllib`. Путь к интерпретатору сохраняется для вызова скрипта заголовков.
Для адаптера и проверки соединения нужен пакет `requests`; MCP SDK не требуется.

## MultipleOptions

Удалённый MCP объявляет `attributes` в `create_work_item` и `edit_work_item` как
словарь строк. Test IT API требует массив ID вариантов для `MultipleOptions`.
JSON-массив, сериализованный в строку, сервер отклоняет.

Адаптер исправляет схемы этих двух инструментов и передаёт их запросы в REST API
`POST /api/v2/workItems` и `PUT /api/v2/workItems`. Значения атрибутов не преобразуются:
строковые атрибуты остаются строками, MultipleOptions — массивами. Остальные
инструменты и промпты направляются в удалённый MCP.

Пример поля «Проект» со значением `front` в `<название проекта>`:

```json
{"attributes": {"xxxx-xxxx-xxxx-xxxx-xxxx": ["xxxx-xxxx-xxxx-xxxx-xxxx"]}}
```

Адаптер не повторяет запросы автоматически. Если создание завершилось таймаутом,
перед повторной попыткой нужно проверить, появился ли кейс в Test IT.

Перезапустите Codex с открытым доверенным проектом. В CLI наличие настройки можно
проверить командой `codex mcp get testit --json`; это проверка конфигурации,
а не подтверждение успешного соединения.

## Проверка без изменений в Test IT

```bash
python3 scripts/check_testit_mcp.py
```

Проверка отправляет только служебные сообщения MCP `initialize`,
`notifications/initialized`, `tools/list` и `prompts/list`. HTTP POST используется
как транспорт MCP; бизнес-инструменты через `tools/call` не вызываются.
Скрипт показывает имена инструментов, промптов и readOnlyHint, а не содержимое проектов
или токен. Аннотация readOnlyHint не подтверждает права пользователя на инструмент.

Проверка локального адаптера через STDIO без изменения данных:

```bash
python3 scripts/check_testit_adapter.py
python3 -m unittest discover -s scripts -p test_testit_mcp_adapter.py -v
```

Параметр `--create-probe` у проверки адаптера разрешает создать служебный кейс
в `<ваш проект>` с атрибутом `demo`. Повторная проверка использует существующий кейс
с тем же точным названием. Этот режим изменяет внешнюю систему; применять его
только по запросу пользователя. Автоматическое одобрение инструментов не включено.
