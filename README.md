# Подготовка QA-артефактов

Проект помогает разбирать требования, составлять чек-листы и тест-кейсы. Решение о корректности результата остаётся за
тестировщиком: между этапами требуется его ревью.

Спецификации по задачам необходимо размещать в `functional_requirements`.

Открой папку проекта в Codex. Правила работы находятся в [AGENTS.md](AGENTS.md), скиллы — в `.agents/skills/`. Можно
написать `run analyse <номер задачи>` или попросить проанализировать требования обычным текстом. Команда `run start <ID>`
продолжает только текущий этап и останавливается на ревью.

| Папка                      | Содержимое                                                         |
|----------------------------|--------------------------------------------------------------------|
| `functional_requirements/` | Спецификации задач                                                 |
| `gui_flows/`               | Скриншоты текущего интерфейса                                      |
| `api_requests/`            | Доступные примеры API                                              |
| `db_mapping/`              | Доступные схемы БД; сами по себе они не описывают бизнес-поведение |
| `customer_flow/`           | Диаграммы пользовательских сценариев                               |
| `drafts/`                  | Черновики до ревью                                                 |
| `ready_artifacts/`         | Согласованные анализы, чек-листы и тест-кейсы                      |

[Схема процесса](AGENTS_SCHEMA.drawio.svg) сохранена в редактируемом SVG из diagrams.net. Она показывает ход работы, а
точные имена файлов и условия перехода определяет `AGENTS.md`.

## Подключение к Test IT

Каждый тестировщик подключается со своим токеном. Доступные проекты и действия
определяются правами владельца токена. Для настройки нужен Python 3.10 или новее.
Все команды ниже выполняются из корня проекта в терминале с выбранным Python
или активированным виртуальным окружением.

1. Установите зависимости:

   ```bash
   python3 -m pip install requests
   ```

   Для Python 3.10 дополнительно установите `tomli`:

   ```bash
   python3 -m pip install tomli
   ```

2. Создайте в корне проекта локальный файл `.env` и укажите адрес вашей команды
   без суффикса `/mcp` и личный токен Test IT:

   ```dotenv
   URL_TESTIT_ADDRESS=https://ваша-команда.testit.software
   TOKEN_TEST_ID=ваш_личный_токен
   ```

   Не передавайте свой `.env` вместе с проектом и не добавляйте его в репозиторий.
   Если файл уже существует, измените только эти две переменные.

3. Установите подключение через локальный MCP-адаптер:

   ```bash
   python3 scripts/install_testit_mcp.py --adapter --replace-testit
   ```

   Установщик создаст или обновит запись `testit` в `.codex/config.toml` и запишет
   пути к Python и адаптеру на вашем компьютере. При замене существующей записи
   он сохранит резервную копию конфигурации; остальные настройки сохранятся.
   Выполните эту команду также после переноса проекта или смены виртуального
   окружения: готовые конфигурации могут содержать пути с другого компьютера.

4. Перезапустите Codex с открытым проектом.

5. Проверьте подключение без изменения данных Test IT:

   ```bash
   python3 scripts/check_testit_mcp.py
   ```

   Скрипт проверяет соединение с удалённым MCP и получает список инструментов
   и промптов. Чтобы проверить подключение из самого Codex и права чтения,
   попросите: «Проверь подключение к Test IT и покажи доступные проекты».

Локальный адаптер поддерживает массивы значений атрибутов `MultipleOptions`
при создании и редактировании тест-кейсов. Токен читается из `.env` и не записывается
в конфигурацию MCP. Подробности — в [TESTIT_MCP.md](TESTIT_MCP.md).

Скрипт `check_testit_adapter.py` привязан к проекту, указанному в настройках. Его режим
`--create-probe` создаёт пробный тест-кейс; для обычной проверки подключения
используйте команду из шага 5.
